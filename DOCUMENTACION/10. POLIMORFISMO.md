# POLIMORFISMO

El polimorfismo permite que un mismo método se comporte de manera diferente según la clase que lo implemente. En Java se logra principalmente mediante la sobreescritura de métodos (`@Override`) en clases hijas o en clases que implementan una interfaz. El objeto "decide" qué versión del método ejecutar en tiempo de ejecución.

## @Override (Sobreescritura de métodos)

```java
// La anotación @Override indica que estamos redefiniendo un método del padre
public class ClaseHija extends ClasePadre {
    @Override
    public TipoRetorno nombreMetodo() {
        // nueva implementación específica de la hija
        return valor;
    }
}
```

## Ejemplo: Polimorfismo con herencia

```java
// Clase padre abstracta
public abstract class Persona {
    private String nombre;
    public Persona(String nombre) { this.nombre = nombre; }
    public String getNombre() { return nombre; }
    public abstract String obtenerDescripcion(); // cada hijo define la suya
}

// =====================================================================//

public class Pasajero extends Persona {
    @Override
    public String obtenerDescripcion() {
        return "Pasajero: " + getNombre(); // comportamiento específico
    }
}

public class Piloto extends Persona {
    private String licencia;
    @Override
    public String obtenerDescripcion() {
        return "Piloto: " + getNombre() + " - Licencia: " + licencia; // diferente
    }
}

// =====================================================================//

// Uso polimórfico: una lista de Persona puede contener Pasajeros y Pilotos
List<Persona> personas = new ArrayList<>();
personas.add(new Pasajero("P001", "Laura"));
personas.add(new Piloto("P002", "Carlos", "LIC-001", 2500));

// Java llama al método correcto automáticamente
for (Persona p : personas) {
    System.out.println(p.obtenerDescripcion());
    // "Pasajero: Laura"  → ejecuta Pasajero.obtenerDescripcion()
    // "Piloto: Carlos..."  → ejecuta Piloto.obtenerDescripcion()
}
```

## Ejemplo: Polimorfismo con herencia multinivel

```java
abstract class Cuenta {
    protected double saldo;
    public abstract void depositar(double monto);
    public abstract void retirar(double monto);
}

// CuentaBancaria implementa el comportamiento base
public class CuentaBancaria extends Cuenta {
    @Override
    public void depositar(double monto) {
        this.saldo += monto;
    }
    @Override
    public void retirar(double monto) {
        this.saldo -= monto;
    }
}

// CuentaAhorro cambia el comportamiento de depositar (agrega interés)
class CuentaAhorro extends CuentaBancaria {
    @Override
    public void depositar(double monto) {
        double interes = monto * 0.02; // 2% de interés
        double total = monto + interes;
        this.saldo += total; // comportamiento diferente al padre
    }
}

// CuentaCorriente cambia el comportamiento de retirar (permite sobregiro)
class CuentaCorriente extends CuentaBancaria {
    private double limiteSobregiro = 200.0;
    @Override
    public void retirar(double monto) {
        if (monto <= (this.saldo + limiteSobregiro)) {
            this.saldo -= monto; // permite retirar más del saldo
        }
    }
}
```

## Sobreescritura de toString()

El método `toString()` viene de la clase `Object` (padre de todas las clases en Java). Se sobreescribe para personalizar cómo se muestra un objeto al imprimirlo.

```java
public class Estudiante {
    private String nombre;
    private String id;
    private NivelCurso nivel;

    @Override
    public String toString() {
        return nombre + "(" + id + ") - Nivel: " + nivel;
    }
}

// Al usar System.out.println(estudiante) Java llama a toString() automáticamente
```

## Sobreescritura de equals()

El método `equals()` viene de `Object`. Se sobreescribe para definir cuándo dos objetos son "iguales" según la lógica de negocio (ej. mismo ID).

```java
import java.util.Objects;

public class Estudiante {
    private String id;

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;                    // misma referencia
        if (!(o instanceof Estudiante)) return false;  // tipo diferente
        Estudiante e = (Estudiante) o;
        return Objects.equals(id, e.id);               // comparar por ID
    }
}
```

- `@Override` no es obligatorio pero es **muy recomendado**: ayuda al compilador a verificar que realmente estás sobreescribiendo un método del padre.
- El polimorfismo permite usar una **variable de tipo padre** para manejar **objetos de tipo hijo**.
- Los métodos más comunes a sobreescribir son `toString()`, `equals()` y los métodos abstractos del padre.
